# Huisheng Chart 在线图表编辑与生成工具项目计划书

## 1. 项目概述

Huisheng Chart 是一个面向大学课程学习、课程设计和项目报告场景的在线图表编辑与生成工具。项目长期目标是支持流程图、ER 图、树状图、UML 图、算法结构图等常见课程图表。第一阶段 MVP 聚焦数据库课程中最常见、价值最高的一条闭环：用户输入 MySQL 建表 SQL，系统自动生成可编辑的 Crow's Foot ER 图和陈氏 ER 图，并提供数据字典、Mermaid 源码、关系说明报告和图片导出。

本项目不是静态图片生成器，而是在线可编辑画布工具。生成后的节点和边必须保留结构化模型，用户可以继续拖拽节点、调整布局、切换视图并导出结果。

## 2. 项目背景

在数据库原理、软件工程、数据结构、系统分析与设计等课程中，学生经常需要绘制各种图表用于作业、实验报告和课程设计。现有工具通常存在以下问题：

- 通用绘图工具自由度高，但从 SQL 或文本自动生成图表能力弱。
- Mermaid、PlantUML 等文本图工具适合源码化管理，但交互式编辑能力不足。
- ERD 专用工具多偏向 Crow's Foot 物理模型，对课程教材常用的陈氏 ER 图支持不足。
- AI 生成图像通常不可精确编辑，节点与连线难以保持数据绑定。
- 自动排版不稳定时，节点重叠、线穿节点和图面混乱会降低课程报告可用性。

因此，本项目采用“结构化解析 + 可编辑画布 + 自动布局 + 多格式导出”的路线，先把 SQL 到 ER 图的核心路径做扎实，再扩展到更多课程图类型。

## 3. 建设目标

### 3.1 总体目标

建设一个在线图表生成与编辑平台，能够把课程中的结构化输入转换为可编辑图表，并支持后续人工调整、自动排版和报告导出。

### 3.2 第一阶段目标

第一阶段完成 MySQL SQL 到 ER 图的 MVP，满足以下目标：

- 支持输入 MySQL `CREATE TABLE` 和常见 `ALTER TABLE ... FOREIGN KEY` 语句。
- 解析表、字段、类型、主键、唯一键、外键、表注释和字段注释。
- 生成统一 ER 数据模型，作为所有视图和导出的数据基础。
- 生成 Crow's Foot ER 图和陈氏 ER 图两种视图。
- 图中节点和边可编辑，拖动节点时边线保持绑定。
- 使用自动布局避免节点重叠，提供“自动整理”能力。
- 支持 Mermaid ER 源码、Markdown 数据字典、Markdown 关系报告、PNG 和 SVG 导出。
- 在 SQL 解析失败时给出错误提示，不破坏用户输入。

## 4. 用户与使用场景

目标用户包括：

- 数据库课程学生：根据建表 SQL 生成 ER 图、数据字典和报告材料。
- 软件工程课程学生：在需求分析和概要设计阶段绘制系统结构图。
- 教师和助教：快速检查学生数据库设计结构和关系完整性。
- 开发者和学习者：从 SQL 反向理解数据模型。

典型流程：

1. 用户打开 Huisheng Chart 工作台。
2. 在左侧输入或粘贴 MySQL 建表 SQL。
3. 点击“生成”。
4. 系统解析 SQL 并生成统一 ER 模型。
5. 默认展示 Crow's Foot ER 图。
6. 用户切换到陈氏 ER 图、Mermaid、数据字典或关系报告。
7. 用户拖动节点或点击“自动整理”调整布局。
8. 用户导出 PNG、SVG、Mermaid 或 Markdown 内容用于课程报告。

## 5. 功能范围

### 5.1 MVP 已纳入范围

| 模块 | 功能 |
| --- | --- |
| SQL 输入 | 提供 MySQL SQL 文本输入区和生成按钮 |
| SQL 解析 | 解析表、字段、主键、唯一键、外键、注释和 ALTER 外键 |
| ER 模型 | 建立统一 `ErModel`，区分真实外键和推断关系 |
| Crow's Foot ER | 表节点、字段行、PK/FK/UK 标记、关系边和基数标签 |
| 陈氏 ER 图 | 实体矩形、属性椭圆、关系菱形、基数标注 |
| 编辑画布 | 基于 React Flow 的节点拖拽和边绑定 |
| 自动排版 | 基于 ELK 的布局和节点重叠检测 |
| 导出 | Mermaid、数据字典、关系报告、PNG、SVG |
| 错误处理 | SQL 解析错误提示和安全解析包装 |
| 验证 | Vitest、ESLint、生产构建和浏览器烟测 |

### 5.2 MVP 暂不纳入范围

- 多人实时协作。
- 用户账号、云端项目管理和历史版本。
- 完整 draw.io 级别的通用图形编辑。
- AI 自动改写 SQL 或自动替换用户输入。
- 所有数据库方言的完整解析。
- 完整流程图、UML、树状图等多图类型编辑器。

这些能力作为后续阶段扩展，不影响第一阶段的 SQL 到 ER 图闭环。

## 6. 非功能需求

- 可编辑性：生成结果必须是结构化节点和边，不是静态图片。
- 绑定性：边必须绑定到节点或字段 handle，节点移动时边线自动跟随。
- 可读性：自动布局后节点不应重叠，线尽量不穿过节点主体。
- 可降级：没有 AI 能力时，SQL 解析、图生成、编辑和导出仍可正常使用。
- 可测试：核心解析、模型转换、布局和导出都必须有自动化测试。
- 可扩展：后续图类型应复用统一建模、画布和导出思路。

## 7. 技术方案

### 7.1 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端框架 | React 18、TypeScript、Vite |
| 图编辑画布 | `@xyflow/react` |
| 自动布局 | `elkjs` |
| 图片导出 | `html-to-image` |
| 测试 | Vitest、Testing Library |
| 代码质量 | ESLint 9 flat config |
| 文本导出 | 自建 Mermaid 与 Markdown exporter |

### 7.2 架构分层

```text
MySQL SQL
  -> SQL Parser / Safe Parser
  -> Canonical ER Model
  -> Diagram Adapters
  -> ELK Layout
  -> React Flow Canvas
  -> Exporters
```

核心目录：

- `src/domain`：统一 ER 模型、示例 SQL 和模型测试。
- `src/sql`：MySQL 解析器和安全解析结果。
- `src/diagram`：Crow's Foot / 陈氏 ER 适配器、React Flow 类型、ELK 布局。
- `src/components`：画布、自定义节点和自定义边。
- `src/export`：Mermaid、Markdown、PNG/SVG 导出工具。

### 7.3 数据模型

统一模型以 `ErModel` 为核心：

- `tables`：表、字段、主键、唯一键、注释。
- `relations`：来自真实外键的关系。
- `inferredRelations`：来自规则推断的候选关系。
- `layouts`：不同图视图的布局信息。

这种模型可以避免每个图类型重复解析 SQL，也便于未来扩展流程图、UML 和树状图。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| MySQL DDL 语法差异多 | 解析失败或遗漏外键 | 持续补充解析测试，保留安全错误提示 |
| 大型图布局复杂 | 节点和线条可能拥挤 | 使用 ELK 布局，增加重叠检测和局部重排 |
| 陈氏 ER 图缺少成熟参考实现 | 实现成本高 | 自建 React Flow 节点，保持模型清晰 |
| 图片导出依赖浏览器 DOM | 导出可能受样式影响 | 使用真实浏览器烟测，后续增加端到端下载测试 |
| AI 输出不稳定 | 课程报告可能不准确 | AI 仅作为增强，核心模型和导出保持确定性 |
| 首屏依赖包变大 | 加载体验下降 | 对 ELK 和图片导出使用按需加载 |

## 13. 后续迭代路线

近期优先事项：

1. 增强画布编辑能力：字段编辑、关系编辑、节点增删、撤销重做。
2. 增强 SQL 解析覆盖：复合外键、更多默认值、更多 MySQL 表选项。
3. 增强导出能力：复制 Mermaid、下载 Markdown、完整画布截图优化。
4. 增强布局质量：边避障、关系分组、陈氏图属性环绕布局。
5. 增加流程图和 UML 图的最小闭环。

中长期方向：

- 建立通用 Diagram Model，统一管理不同图类型。
- 支持自然语言或结构化文本生成图。
- 支持课程报告模板生成。
- 支持项目保存、版本历史和多人协作。
- 支持导入 Mermaid、PlantUML、DBML 等文本图格式。

## 14. 结论

Huisheng Chart 的第一阶段选择 SQL 到 ER 图作为 MVP，是因为该场景需求明确、课程价值高、技术路径可验证，并能沉淀后续多图类型所需的核心能力：结构化模型、可编辑画布、自动布局、节点边绑定和多格式导出。

当前版本已经完成第一阶段的基础闭环。下一阶段应围绕“编辑能力增强”和“多图类型扩展”继续推进，把项目从 SQL ER 图工具逐步升级为面向大学课程的通用在线图表生成与编辑平台。
